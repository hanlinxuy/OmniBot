It was derived from `artifacts/omniflow-gui-runtime-2.1.8.zip`, entry `scripts/runtime/python/omniflow/runtime/semantic_grounding.py` (original SHA-256 `eef292189fdc508d087ac16e133f8ffe74abe95b8a744b16b1199aad5ebaf388`). Compare this exact source hash against `get_omniflow_python_override` before applying; do not overwrite a different source or existing override. Apply as `omniflow/runtime/semantic_grounding.py` with the official whole-file tool. The tool validates, reloads and rolls back on failure; `clear_omniflow_python_override` restores pinned behavior. These candidates have been applied through the official interface on the development vivo device; see the scan report for actual outcomes. Application success is not task success.

The focused change allows a uniquely matched, enabled, visible, focusable labeled node to supply its own gesture bounds when no clickable ancestor exists. It recognizes short exact labels with a narrow button/key/按钮/数字键 role wrapper, and the exact text + content-desc combination from the same node; ambiguous and arbitrary longer descriptions still fall back. It also respects Android XML `visible-to-user=false`. A focusable node does not prove a gesture will activate it: device execution and independent result verification remain necessary.

Run `python3 -m unittest discover -s scripts/android-scenario-scan/overrides -p 'test_*.py' -v` from repository root. The private real-device XML test skips if the local session evidence is unavailable.

## Bounded local controls (Mika study)

`controls.py` is a new independently implemented module for the official override path `omniflow/runtime/controls.py`. It exposes `ui_steps`, `set_wheel` and `wait_until` to the existing GUI planner; the paired planner/engine changes execute every primitive through the existing guarded action and RunLog path. `core.py` is a full-file candidate derived from the pinned archive's `omniflow/runtime/core.py` (original SHA-256 `d0b5b38afe806774d6d64d29b2f36fea37a4bdc07f485494d23904492a828b2e`); it skips the fixed one-second settle only after explicit host completion with `stable` or `completed_by_action`. `runtime_delegated`, timeout, and missing diagnostics retain the old wait.

Check current device source against the committed version or pinned source before applying; preserve unrelated existing overrides. Build/install the Android node-actions changes while idle, apply `controls.py` and `core.py`, then `planner.py`, then `engine.py` through the official interface. Read back every source and hash. Do not alter the runtime ZIP. Rollback must restore the exact saved pre-change planner/engine/core sources, then remove the new module only after its importers are restored; do not clear all unrelated overrides.

The native Android changes include advertised accessibility click, bounded NumberPicker/SeekBar native scroll, editable NumberPicker focus commit, and XML actions/range. Dates on a picker without year expose only month/day; device date supplies context, not persisted-year proof. This initial implementation does not copy Mika's OCR or multi-step native scroll bursts. See `docs/research/mika-local-ui-controls.md` and `docs/testing/android-mika-controls-2026-10-31.md` for source provenance, actual device evidence, and failed attempts. The immutable runtime remains unchanged, so a fresh install still needs the official override deployment; these files are not silently injected into release builds.

The control-loop performance follow-up reuses the prior guarded action's fresh `after` observation for the next `ui_steps` member; it still refreshes at entry and when no post-action observation is returned. Each action retains the same guard, cancellation and RunLog path. Timing fields separate host-side dispatch/stabilization and action-after screenshot observation from batch refresh and local waits; do not add nested totals together. One two-action same-start device comparison reduced batch refreshes from two to one, but differing model and wait times prevent a general speed claim. See `docs/testing/android-mika-terra-batch-2026-10-31.md`.

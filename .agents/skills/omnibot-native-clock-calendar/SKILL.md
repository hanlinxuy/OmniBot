name: omnibot-native-clock-calendar
description: Use OmniBot's native Android alarm, timer, and calendar tools and verify their effects without conflating dispatch with success.
---

Use for authorized Android system alarms, timers, or calendar events through OmniBot's existing Agent or MCP tools. Discover the available tool surface and current device state before use; this repository file is not proof that the Android app has installed or automatically loaded this skill.

For a system clock alarm, call `alarm_reminder_create` with `mode=clock_app`, a user-specified title and ISO `triggerAt`; `repeatDays` uses ISO weekdays 1=Monday through 7=Sunday. Use all seven days only when daily repetition was requested. `exact_alarm` is a separate app reminder and does not support recurring weekdays. For a timer use `timer_create` with a positive integer `durationSeconds`, optional title and `skipUi` as appropriate. Both clock tools dispatch an Intent; `creationVerified=false` means that neither creation nor running state has been independently established. Reuse the current clock page when it already satisfies the target state; do not relaunch the app or click its selected tab just to verify it. Inspect the actual target clock state before reporting success; the native timer tool has no cancellation operation.

For calendar work, use `calendar_list` to select the intended authorized calendar, then `calendar_event_create` with the requested time, time zone and `reminderMinutes`. Independently query `calendar_event_list`; match the intended event and verify the returned reminder values, including `[]` when there is no reminder. For a permitted deletion, verify the event identity and ownership, use `calendar_event_delete`, and read back its absence. Do not substitute a creation receipt for a later independent read.

Preserve existing alarms, timers, calendars, and user data; distinguish dispatch, independent verification, and any assisted cleanup. Use actual user-supplied times and the selected calendar, without assuming a fixed ID or time zone. Respect existing access policy and current authorization; never repeat an uncertain write. Device-specific GUI navigation between similarly named apps may be unreliable: verify the foreground app and obtain fresh observations. For development regression workflows, see `../omnibot-android-regression/SKILL.md` and the case manifest.

# Smile scan and daily-memory newline defect — 2026-10-30

A natural normal-chat request asked to draw a face outline, two eyes and a mouth in a uniquely marked note. The persisted ACP turn ended after approximately 10m56s and six GUI component invocations. Independent reopening showed a smile image in that note. The Agent had instead generated and imported an image and textual symbols after failed drawing attempts, so this does not establish the requested in-app hand-drawing path or the original BA21 whiteboard scenario. It incorrectly told the user Notes had no drawing canvas; an earlier device exploration had already demonstrated its graffiti canvas. It also inserted an unrelated existing picture in the test note and later used the note editor to remove it; the original gallery item was not independently audited. The exact marked note was deleted and search confirmed absence.

The Agent created a uniquely marked image under `Pictures/Smile`; its SHA-256 matched the generated image, and the host removed only that marked file. The marked filename was absent afterward from the folder and a media-provider query. The Agent also wrote six unmarked files under `/workspace/smile/`; although the recorded commands wrote those paths, their pre-task existence was not captured. They remain intact pending the user's decision, and the directory was not removed. The case is not counted as an automatic regression pass or fully cleaned.

The turn wrote one marked daily memory. The source file contained exactly one matching test entry but Memory Center could not display it: after the last short-memory deletion the file had retained its day heading without a final newline, and the subsequent append joined the test entry onto that heading. A private pre-append snapshot from the previous cleanup proved that removing the exact test entry returned the file byte-for-byte to its prior contents; the host restored that snapshot only after checking the source hash and verified exact bytes. The memory index directory was empty at inspection. No other memory entry was removed; off-device synchronization was not audited.

The product fix preserves a trailing newline when deletion leaves nonempty content, and both daily-memory and quick-log append paths add a separator when an existing file lacks one. Eleven focused `ShortMemoryDeletionTest` tests passed, including delete-last-then-append and legacy missing-newline cases. The development APK built successfully (SHA-256 `e6a87a9c3546f213ba46b0dd7746edb323394e2e691fc26e3af6ab0eddd79450`); it has **not** been installed or verified on device. This fix does not automatically rewrite already malformed historical entries.

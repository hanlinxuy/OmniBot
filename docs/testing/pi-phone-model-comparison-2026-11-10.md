# 手机 Pi 三模型对比与日历时区修复（2026-11-10）

## 结果与范围

在连接的 vivo 上，实际安装的 Pi 1.4.0 通过 ACP 执行，三种模型均完成了两类合成任务的独立验收：文件内容筛选/复制，以及系统日历创建/修改/删除。修复了更新日程时未显式填写 timezone 会把区域时区改为固定偏移的产品问题，已构建、安装并真机复验。

这是手机真机上的有限场景对比，不是官方 MobileWorld/iOSWorld 分数，也不是全场景通过或统计排名。文件任务发生在 Pi 的隔离工作目录，不代表 Android 共享存储或所有第三方应用均可访问。

## 运行链路

- 手机 Alpine 的 `omnibot-pi-acp --health` 返回适配器 0.1.0 / Pi 1.4.0；启动器对应 revision `d845427d0813d576fafa`。Ubuntu 没有同一启动器，未推断为整体环境故障。
- Mac 是评测客户端和模型中转，手机上已安装的 Pi 拥有 agent/tool loop。没有启动 Codex 或 Terra agent 代做手机任务，也没有调用另一聊天带队。
- ACP 会话单独创建；原有 OmniBot 界面选中的是小万，其历史任务不计入 Pi 成绩。此处验证了手机 ACP 适配器链路，未测普通聊天 UI 的端到端渲染延迟。
- 模型请求实际包含 37 个工具：Pi 的 read/bash/edit/write，以及 33 个真实手机 MCP 工具。工具可见不代表每个工具都已验证。
- 基础设施探针使用固定响应桩，调用真实 context_environment_get，取得 success=true、ACP tool completed 和 prompt end_turn；该探针不算模型成绩。
- Terra 复用 Mac 当前 Codex/ChatGPT 订阅，准确请求 gpt-6.1-terra。登录凭据只留在 Mac。中转使用 Pi 的 Codex Responses 协议实现转换消息和工具，不增加另一个 agent loop。Node 沿用 Mac 已配置的网络代理。
- 35a3 走已有模型服务的临时 SSH 转发；DeepSeek 只向官方 API 发送其密钥。凭据、完整请求及原始日志不提交到仓库。

## 验收定义

文件：9 个合成文本中，依据正文 type=invoice 且 date 属于 2026-11，复制恰好 3 个文件到 november_invoices。文件名包含误导项及无日期项，另有收据、草稿、其他月份和年份。宿主独立读取手机目录及文件字节，确认目标集合准确、内容一致、全部原文件保留。三者最后均报告金额 250.50，正文另行复核。隔离目录由宿主清理并确认不存在，不记为模型自主清理能力。

日历：仅在 calendarId=1 操作带唯一标题的测试事件。第一轮创建 2026-11-12 上海时间 10:00–10:40、测试会议室、提前 15 分钟提醒；第二轮延后半小时、时长不变、提醒改 5 分钟、其他信息不变；第三轮核对标题/ID 后删除。每轮结束后宿主通过独立 MCP 连接查询实际日历状态。修复后的验收包含 eventId、calendarId、时间、地点、时区、allDay、提醒和最终查询为空，三者均无需宿主补删。

当前任务全部使用文件/终端或日历系统工具，没有把 GUI 点按当成必要前提。银行、支付、微信及用户排除的包未纳入测试；没有读取其他个人日程或票据。

## 发现、修复与失败记录

1. **日历产品缺陷**：35a3 和 Terra 在更新时间时省略 timezone，工具把原 Asia/Shanghai 存为 +08:00。当前日期的显示时间虽相同，区域时区信息已丢失，不符合“其他信息不变”。updateEvent 原本选择了存量时区，却允许带偏移的输入覆盖它；现改为始终使用解析后的目标区域时区，显式传入新 timezone 时仍使用新时区。创建语义未改变。
2. **验收缺口**：第一版脚本漏查 timezone，曾产生过宽的 passed 标记。保留原始结果，新增 validity-audit 标明不得计完整通过；修正验收后，对修复版三模型全部重跑。
3. **Terra 中转缺陷**：最初直接调用 provider stream，缺少新版 SDK transcript normalization，导致上游没有工具。另一次声明控制因协议的工具增量表示触发检查。均不计模型失败；统一声明形式后，发送前核验 37 个上游工具，再运行任务。
4. **凭据区别**：Pi 自己的旧登录在刷新时收到地区不可用 403；本机 Codex 登录是另一份有效订阅凭据，实测可用。未用其他 Terra 版本替代。
5. **传输失败**：35a3 首轮日历的删除后模型流中断，ACP 返回 terminated，实际删除已独立确认，未重放；后续一次 SSH 转发断开在首次请求前失败。Terra 一次日历首请求 fetch failed，未创建日程。无效轮次和清理证据保留，恢复连接后使用新标记运行。
6. **仍有限制**：ADB run-as 启动时有 /sdcard 和 /proc/self/fd 绑定警告。已验证的隔离文件与真实日历工具不受其影响；共享存储访问未据此认定成功。系统闹钟/计时器工具虽存在，本轮没有将 Intent 派发等同于实际创建成功。

## 发现与修复

### Pi 产品运行时：小上下文原生压缩

35a3 的 32K 上下文任务出现输出预算压到 1 token 后停止。保存的 Pi 会话显示默认 20K 保留预算超过部分历史的估算长度，导致找不到可压缩前缀。现在按模型窗口缩放保留与预留预算，在 SettingsManager 创建时写入，保留 Pi 原生压缩及续跑所有权，不在宿主重放任务。

验证：28 项 Pi ACP 测试通过，生成安装资源校验通过；新版已部署 vivo，真机文件读写、bash、MCP、身份恢复、取消与子进程清理通过。

原失败 mem-043 复测出现一次原生 compaction（tokensBefore=28561），9 次模型请求后在原 ACP prompt 内 end_turn；测试目录和 ADB reverse 清理确认。但回答将 completed 住宿写成 upcoming，并误报赛事场馆与旅行历史，因此业务验收仍失败。这证明运行时恢复生效，不代表任务正确率已经解决。

### 适配器改进

- 只暴露当前 fixture 实际具备的工具，减少无关 schema。
- 大型嵌套记录返回可继续查询的路径和分页，避免一次耗尽上下文；字段投影也保留正确来源索引。
- 增加频道索引、结构化时间转换和精简文件目录。
- 先检查模型可达性，再创建手机测试状态；传输错误独立记为基础设施失败，不重放不确定的修改。
- 保存本次私有 Pi 会话用于定位压缩问题，公开结果不包含凭据或原始私人会话。

13 项工作区适配器测试、5 项原始 SQL 判题/汇总/清理测试通过。其他已确认问题包括：模型把“计划开始 QA”改写为“QA 已通过”、跨店购买、预算计算不准以及日期/时区误读。已保留失败证据，不用工具调用成功替代业务验收。
